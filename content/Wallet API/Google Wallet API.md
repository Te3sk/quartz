# Introduction
[Official Doc](https://developers.google.com/wallet/tickets/events?authuser=1)
* **Pass Issuer:** The Passes issuer is the entity that owns the pass and is responsible for issuing passes to their customers. This could be you, the developer, or the organization that you represent. In order to become a Passes Issuer, you must first register as an Issuer.
* **event ticket class:** A `EventClass` can be thought of as scheduled event. An issuer may create multiple scheduled events with permutation of event names and timings. Each `EventClass` representing a scheduled event may contain its own appearance and data fields to meet the venue-specific requirements. In addition, `EventClass` can also be used to enable additional features like Smart Tap.
* **event ticket object:** A event ticket object is an instance of a `EventClass`. A new `EventObject` instance should be created for each customer that is distributed with a event ticket. A `EventClass` is a type of Pass Class. Pass Classes describe general information for related Pass Objects (such as style and appearance), and do not include customer details.
* **Pass Object:** A `EventObject` is a type of Pass Object. Like `EventObjects`, a Pass Object is an instance of a corresponding Pass Class. A Pass Object should be created for each customer that is issued a event ticket. Pass Objects contains customer-specific information. For example, it can be used to identify that a customer not only has a ticket for a event, but also identify which seat on the event they’ve been allotted.
* **Service account:** The service account is the identity that is used to call the Google Wallet API. Permission to access the Passes API should be granted to this service account. The service [[Google Wallet API Key Concept & Terminology#Service account key|account key]] is the credential used to authenticate your application as the service account. The service account key should be considered highly sensitive and kept private. If a third party has access to the service account key, they will be able to identify themselves as the service account and perform actions that the service account is permitted to perform.

## Adding a pass to a user's Google Wallet

To add a [[Google Wallet API Key Concept & Terminology#Pass|pass]] to a user's Google Wallet, you create a [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JSON Web Token (JWT)]] that contains claims you (the issuer) are making about the [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] instance that will be saved in the user's Google Wallet - most importantly, the Object ID of the [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] instance you are issuing to the user. The [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]] is then delivered to the user via the a [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' button|'Add to Google Wallet' button]] or an [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' link| Add to Google Wallet link]].
After a user clicks the button or link to add an issued pass into their Google Wallet, a link the [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] instance encoded in the [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]] is linked to that user's Google account. This means that when the user clicks the button again, a link already exists to that [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]], so duplicate copies won't be added to the user's wallet.
If a user removes a pass from the Google Wallet app, the corresponding [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] instance is automatically de-linked from the user, but it is not deleted. This means that a user can click the **Add to Google Wallet** button or link again, to save the pass without the need for a new [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] instance or [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]] to be created.
## Google Wallet pass development flow
[Official Doc](https://developers.google.com/wallet/tickets/events/overview/add-to-google-wallet-flow?authuser=1)
### 1. Create a Passes Class
A [[Google Wallet API Key Concept & Terminology#Passes Class|Passes Class]] defines a set of properties that are common across multiple passes, similar to a template. For example, if you were issuing tickets of an event, the Passes Class would define fields that are the same across all tickets, such as the event name, date, and time.

Every pass you issue must reference a [[Google Wallet API Key Concept & Terminology#Passes Class|Passes Class]]. You must also assign a unique ID to every Passes Class you create, which is used to reference it in when creating passes.

A [[Google Wallet API Key Concept & Terminology#Passes Class|Passes Class]] is defined in JSON format, and can be created with the [[Google Wallet API Key Concept & Terminology#Google Wallet REST API|Google Wallet REST API]], [[Google Wallet API Key Concept & Terminology#Google Wallet Android SDK|Android SDK]], or in the Google Wallet Business Console.
### 2. Create a Passes Object
A [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] defines the properties of a unique pass that will be issued to a specific user. For example, the [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] for an event ticket would define fields that are unique to a specific ticket, such as the seat number or a QR code for that ticket.

When a [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] is created, the Google Wallet API stores a new pass and associates it with your Issuer account. This stored pass is a combination of the unique properties of the [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] and the template properties of the associated [[Google Wallet API Key Concept & Terminology#Passes Class|Passes Class]].

You must also assign each [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] a unique ID, which is used to reference it when issuing a pass.

A [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] is defined JSON format, and can be created with the [[Google Wallet API Key Concept & Terminology#Google Wallet REST API|Google Wallet REST API]] or [[Google Wallet API Key Concept & Terminology#Google Wallet Android SDK|Android SDK]].
### 3. Encode the pass in a JSON Web Token (JWT)
To issue a pass to a user, a [[Google Wallet API Key Concept & Terminology#Passes Class|Passes Class]] and [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] must be encoded in a JSON Web Token ([[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]]). The JWT format is a common and open standard for representing claims between two parties. In the case of issuing passes with the Google Wallet API, JWTs are used to send a claim that a user has a right to access a specific pass that is associated with your Issuer account.

When a [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]] is sent to the Google Wallet API, the encoded data is used to identify a specific pass and issue it to the user. If the pass has already been issued, this data also allows the Google Wallet API to identify that the pass is a duplicate so that it is not added to the user's Google Wallet more than once.

[[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]]s are defined in JSON format based on the [JWT specification](https://datatracker.ietf.org/doc/html/rfc7519). To define a JWT for issuing a pass with the Google Wallet API, you provide the information about the pass you wish to issue in the `payload` property of the JWT.
### 4. Sign the JWT with your credentials
All [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]]s sent to the Google Wallet API to issue a pass must be signed with credentials you have previously provided in the Google Wallet Business Console. Signing uses your credentials to encrypt the JWT so that your passes remain secure, and to allow the Google Wallet API to authenticate that the the pass details encoded in it are valid and associated with your Issuer account.

The Google Wallet client libraries and the [[Google Wallet API Key Concept & Terminology#Google Wallet Android SDK|Android SDK]] provide convenience methods to sign your [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]]s. There are also numerous open-source libraries available that handle the complexity of code signing for you to choose from.

For those using the [[Google Wallet API Key Concept & Terminology#Google Wallet REST API|Google Wallet REST API]] to issue passes, the [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]] is signed with a [[Google Wallet API Key Concept & Terminology#Service account key|Google Cloud Service Account key]]. For those using the Google Wallet [[Google Wallet API Key Concept & Terminology#Google Wallet Android SDK|Android SDK]], the SDK automatically handles signing the JWT with the SHA-1 fingerprint of your app signing certificate.

To protect your credentials, JWTs should only be signed on your server or using the Google Wallet [[Google Wallet API Key Concept & Terminology#Google Wallet Android SDK|Android SDK]] in your app.
### 5. Issue the pass with an 'Add to Google Wallet' button or link
Once you have created a signed [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]], you are ready to issue your pass to a Google Wallet user! This is done by either presenting the user with a [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' button|'Add to Google Wallet' button]] or [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' link|link]]. When a user clicks the button or hyperlink, the signed JWT is sent to the Google Wallet API, which then decrypts it using your saved credentials. Once the JWT signature is authenticated, the pass will be issued to the user to save in their Google Wallet.

To create a [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' button|'Add to Google Wallet' button]] for an Android app, use the Google Wallet [[Google Wallet API Key Concept & Terminology#Google Wallet Android SDK|Android SDK]], which provides methods for generating the button. For all other platforms, including web, email, and text message, create a hyperlink in the format `https://pay.google.com/gp/v/save/<signed_jwt>`. Where possible, it is best to deliver this link to the user as a [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' button|'Add to Google Wallet' button]].

For more information on using the [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' button|'Add to Google Wallet' button]], see the Google Wallet API [Brand guidelines](https://developers.google.com/wallet/tickets/events/resources/brand-guidelines?authuser=1)
## Creating Passes Objects and Passes Classes in the JWT
[[Google Wallet API Key Concept & Terminology#Passes Class|Passes Classes]] and [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]]s may be created in advance using the [[Google Wallet API Key Concept & Terminology#Google Wallet REST API|Google Wallet REST API]] or [[Google Wallet API Key Concept & Terminology#Google Wallet Android SDK|Android SDK]]. Once created, they are then used to issue passes by referencing their ID.

Alternatively, you may also create [[Google Wallet API Key Concept & Terminology#Passes Class|Passes Class]]es and [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]]s 'just in time' by embedding their JSON directly in the [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]] that is used to issue the pass to a user. In this method, the Passes Classes and [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]]s are created by the Google Wallet API when the signed JWT is sent using a [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' button|'Add to Google Wallet' button]] or [[Google Wallet API Key Concept & Terminology#'Add to Google Wallet' link|link]].

For example, the following shows a [[Google Wallet API Key Concept & Terminology#JSON Web Token (JWT)|JWT]] with a new [[Google Wallet API Key Concept & Terminology#Passes Class|Passes Class]] and [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Object]] defined using the `payload.eventTicketClasses` and `payload.eventTicketObjects` properties. Notice that these properties are arrays, so they can accept one or more Passes Classes or [[Google Wallet API Key Concept & Terminology#Passes Object|Passes Objects]]. You may also specify just a new Passes Object in the JWT that references an existing Passes Class by its ID.
